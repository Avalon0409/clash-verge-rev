# Clash Verge App Proxy 常见问题

<a id="windows-application-updates"></a>
## Windows 应用更新后，为什么出现旧应用或需要重新配置？

Windows 使用完整 EXE 路径识别应用。安装器把新版放进新的版本目录后，旧路径和新路径会成为两个条目。点击应用列表顶部的刷新按钮，会检查保存的路径并清理已经不存在的应用和配置，然后重新扫描安装入口。磁盘上仍存在的旧 EXE 会保留。

希望沿用原设置时，先记下旧条目的开关、路由模式、订阅和节点，再刷新列表并选择新版 EXE，给新版恢复这些设置。刷新清理会删除已不存在路径的保存配置；无法读取路径时会报错，并保留原配置。

当前的自动继承覆盖父子进程。应用跨版本升级继承需要稳定的安装身份，尚未加入此版本。

## 为什么 macOS 通常能沿用应用配置？

macOS 通常在同一路径替换 `.app` 包，例如 `/Applications/Example.app`。应用包路径保持稳定，包内主进程和辅助进程继续匹配该配置。移动应用、改名或重新安装到不同目录后，需要重新选择应用路径。

<a id="service-core-permissions"></a>
## Windows 服务或 TUN 启动失败

在设置中查看服务状态，并使用客户端提供的安装或修复入口。服务权限检查失败时，按照提示修复数据目录所有权或权限；核心被另一个程序占用时，先停止该程序，再启动本客户端的核心。查看日志中的具体操作和错误信息后再重试。

## 启用应用代理后，其他程序仍使用代理

查看是否同时开启系统代理，以及该程序是否设置了独立的 HTTP/SOCKS 代理。检查纯应用分流时，关闭系统代理和程序自己的代理设置，再检查连接页中的实际进程与节点。

## 升级后找不到应用分流功能或路由异常

确认安装的是 [本仓库](https://github.com/Avalon0409/clash-verge-rev/releases) 的 `app-proxy` 发行包，并在核心设置中加载配套的内置核心。客户端和核心共同提供应用分流功能。

## Freecat 登录失败或换电脑后无法刷新

确认 HTTPS 服务地址、账号和密码正确，然后重新登录。账号秘密保存在当前系统的 Keychain 或 Credential Manager 中；复制配置文件后需要在新系统建立自己的凭据。错误涉及服务端协议变化时，附上版本和错误信息反馈。

## 应用选择了节点，DNS 出口仍异常

核对应用使用的订阅、DNS 覆盖、全局节点与应用节点，并记录连接页和日志里的实际出口。[PR #1](https://github.com/Avalon0409/clash-verge-rev/pull/1) 正在处理这条调用链和 Windows 多网卡选路问题。
